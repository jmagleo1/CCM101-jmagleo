# Reflection – Laboratory 02: Build the Cloud Infrastructure Blueprint

Before this activity, "cloud infrastructure" was just a term I always heard pero wala talaga akong idea kung ano talaga nangyayari sa likod nito. Parang alam ko lang na may mga server somewhere, tapos AWS, Azure, Google Cloud, mga ganon. Pero nung ginawa ko na yung hands-on part gamit yung Linux server sa KillerCoda, doon ko lang na-realize na may structure pala talaga yung compute, storage, networking, tsaka OS, magkakasama silang gumagana para lang tumakbo yung isang VM.

Yung part na pinaka-nag-enjoy ako is yung paggamit ng mga Linux commands, kahit na medyo nakakatakot siya sa una. Yung mga command na parang lscpu, free -h, lsblk, nakakalito tignan sa una lalo na kung hindi mo pa alam ano gagawin nila, pero nung nakita ko na yung output at na-relate ko sa actual na CPU, memory, storage, doon lang siya na-gets ko. Iba rin talaga pag nakikita mo yung numbers mismo kesa basahin lang sa text.

Isa pa sa medyo nahirapan ako is yung GitHub mismo, kasi hindi pa ako masyadong sanay dito. Halos kinakapa ko lang buong process — saan gagawa ng file, paano mag-organize ng folders, paano gumagana yung commit. Medyo nag-trial and error ako, pero unti-unti ko rin nasanay mag-navigate sa repo at mag-upload ng files.

Yung pag-compare naman ng AWS, Azure, at Google Cloud, nakatulong din para makita ko na hindi sila pareparehong-pareho lang kahit magkamukha ang concept nila. Parang akala ko dati same lang sila lahat, kaso pag pinag-aralan mo yung equivalent services nila (EC2 vs Virtual Machines vs Compute Engine), makikita mo na iba-iba pala sila ng strength — mas okay si Azure kung Microsoft ang gamit ng company, tapos si Google Cloud naman known talaga sa AI at Kubernetes.

Siyempre hindi rin smooth lahat. Since bago pa ako sa GitHub, madalas akong nagkakamali minsan sa Markdown formatting, minsan naman nailalagay ko sa maling folder yung file. Medyo nakaka-stress siya minsan lalo na kapag paulit-ulit, pero nakatulong din naman para maging mas maingat ako at mag-double check bago mag-commit.
